# Nirvana's Poke-Archive

공개 사이트: https://pokedex.elmajor710.com/

관리 화면: https://pokedex.elmajor710.com/admin.html

## 운영 방식

- GitHub Pages가 `main` 브랜치의 루트 파일을 배포합니다. `CNAME`은 기존 도메인을 유지합니다.
- Firebase 프로젝트는 `poke-archive-d8e29`입니다. 게임 데이터는 Firestore에 그대로 보관합니다.
- 방문자는 로그인 없이 `isPublished: true`인 자료만 읽습니다. 공개 체크가 없거나 꺼진 자료는 보이지 않습니다.
- 관리자 화면은 기존 운영자 이메일/비밀번호로 로그인합니다. Firestore 규칙에서 허용된 UID만 편집할 수 있습니다. 다른 계정이 생겨도 관리 권한이 생기지 않습니다.
- 관리 화면에서 자료를 저장하고 게시물 관리에서 공개 여부를 선택합니다. 덱을 수정해도 기존 좋아요 수를 덮어쓰지 않습니다.
- 관리자 로그인은 탭 세션에 한정합니다. 사용 후 로그아웃하세요.

## 좋아요

Firebase Authentication → 로그인 방법에서 **익명** 제공업체를 사용 설정해야 합니다. 방문자가 좋아요를 처음 누를 때만 내부 익명 계정을 만들므로 가입 화면은 표시되지 않습니다.

익명 사용자별 덱당 한 표를 기록합니다. 좋아요/취소는 투표 기록과 숫자를 함께 변경합니다. 공개된 덱의 좋아요 숫자 외에 다른 내용은 수정할 수 없습니다. 기존 숫자는 보존됩니다. 과거의 브라우저 로컬 좋아요 기록은 서버 투표 기록으로 변환하지 않습니다.

이 방식은 같은 브라우저의 중복 클릭을 막지만, 다른 기기나 브라우저 저장소 초기화까지 동일인으로 식별하지는 않습니다. 기존 방문자 카운터는 공개 쓰기 권한이 필요했던 방식이라 화면에서 제외했습니다. 기존 통계 데이터는 삭제하지 않았습니다.

## 보안 규칙 관리

`security/firestore.rules.template`의 `__OWNER_UID__`를 Firebase Authentication 사용자 목록에 있는 운영자 UID로 바꿔 Firestore → 규칙에 게시합니다. 자리표시자를 그대로 게시하지 마세요. 운영자 UID를 넣은 개인 파일과 기존 규칙 백업은 `.local/`에 보관하고 Git에 올리지 않습니다.

규칙을 먼저 게시한 다음 익명 로그인을 사용 설정하세요. 방문자에게 일반 데이터 편집 권한을 주거나 `request.auth != null`만으로 관리 권한을 허용하지 마세요.

## 개발 검증

Node.js 22 이상과 Java 21이 필요합니다.

```sh
npm ci
npm run check
npm test
```

UI 검사는 가짜 데이터를 사용하고, 보안 검사는 `demo-poke-archive` Firestore 에뮬레이터만 사용합니다. 실제 운영 데이터를 수정하지 않습니다. UI 단위 검사는 실제 브라우저의 시각적 검증을 대신하지 않습니다.

배포 전 실제 브라우저에서 공개 목록, 덱 상세, 좋아요/취소, 운영자 로그인과 로그아웃을 확인하세요. 운영 데이터의 추가·삭제 테스트는 별도 테스트 프로젝트에서 진행하세요.
